# Inventory Tracking Android Application

An Android inventory management application developed using Java and Android Studio. 
The application allows users to create accounts, manage inventory items, update quantities, and receive an SMS alert when an item's quantity reaches zero.

Technologies:
Java
Android Studio
SQLite
Android SDK
XML

Features:
User login and account creation
Inventory item management
Add, edit, and remove inventory items
Inventory quantity tracking
SMS notification when inventory reaches zero
Responsive UI testing across different screen sizes
Project Highlights
Designed and implemented the SQLite database used by the application.
Developed multiple Android activities for login, inventory management, item creation/editing, and SMS functionality.
Tested the application across multiple screen sizes.
Focused on keeping the interface simple and user-friendly.



# CS360 Reflection #

**/Briefly summarize the requirements and goals of the app you developed. What user needs was this app designed to address?/**

This apps goal was to create a simple and easy to use inventory tracking system. The needs that this app is aimed to address is, to let users easily add, edit and remove inventory items that are on hand. 
There is a built in SMS to alert users when an inventory items quantity reaches zero. 


**/What screens and features were necessary to support user needs and produce a user-centered UI for the app? How did your UI designs keep users in mind? Why were your designs successful?/**

The screens included are a login screen where users can also create accounts. The main inventory screen allows users to search inventory items, edit or remove them. 
There is an add item button that directs to an add screen, this has the options to add item names and quantities. The SMS screen has permission requests and details for SMS use.
I kept the UI very simple and basic to not add unnecessary distractions. 


**/How did you approach the process of coding your app? What techniques or strategies did you use? How could those techniques or strategies be applied in the future?/**

My approach was to create a basic UI and add features then test to make sure those features worked. Updating the UI while add features would be a technique I plan to use in the future to reduce errors.
This will also make UI function and design more in the forefront of development in future. 


**/How did you test to ensure your code was functional? Why is this process important, and what did it reveal?/**

I tested features and UI elements as I added them. I also used two different screen sizes to make sure that the UI work properly on various devices. 
Making sure that code was modular so that new features and updates are easy to introduce.


**/Consider the full app design and development process from initial planning to finalization. Where did you have to innovate to overcome a challenge?/**

I think the biggest challenge for this project was the design step. I'm not much of a designer so my UI layout is very basic, I plan to practice this more to make sure that function does not rule design.


**/In what specific component of your mobile app were you particularly successful in demonstrating your knowledge, skills, and experience?/**

I think that setting up the databases and linking the tables to hold user login info and the inventory lists was a stand out for the last few projects I have done. 
I enjoy working with databases so it was fun to real world use and get to implement it. I also think my code comments are getting much better, and clear in explanation.
